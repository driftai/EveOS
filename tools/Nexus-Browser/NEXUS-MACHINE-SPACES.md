# Nexus Machine Spaces — implementation contract (draft v0.1)

Status: the managed typed-execution slice is implemented on `eve/nexus-machine-spaces`; filesystem capabilities, persistent grants, agent polling, external-terminal attachment, supervised-server sessions, and automatic arbitrary-task completion remain disabled.
Base: main 71fb6d6d1c6665c0436da15ba085c63ab371f76c. Single integration branch: eve/nexus-machine-spaces. Preserve Astro's uncommitted terminal-wrap patch and the currently deployed bridge until a separately qualified cutover.

## Purpose and exact scope

Introduce a third target class, terminal-origin, representing an actual locally authenticated terminal resource, NOT an LLM room member. Make local files, terminals, file editing, managed server sessions and exact-once task completion available in Base mode (one attached terminal) and Dex mode (one room may contain many independent Terminal Spaces). The extension is the UI/transport; an explicitly installed localhost broker owns native computer access. Never pretend a browser content script can execute OS commands or freely inspect the disk.

### Implemented managed-execution slice (2026-10-07)

- Nexus owns bounded managed CMD, Windows PowerShell, PowerShell 7 (when installed), and WSL Bash targets. Arbitrary existing terminal windows remain discovery-only/unsupported.
- Base Mode requires an exact local allow-once confirmation before each command. High-risk commands require the displayed challenge as a second local confirmation.
- Dex rooms can create/archive Machine Spaces, attach/detach managed terminals as resources, and request `terminal_targets`, `terminal_exec`, `terminal_status`, and paged `terminal_output` actions. Agent requests remain pending until local owner approval and never become room participants.
- Execution is serialized per target, uses explicit executables with `shell:false`, and is bounded to 30 seconds and 1 MiB. Timeout, interrupt, or output overflow is recorded as outcome-unknown and is never replayed automatically.
- Output stays in an audience-scoped bounded localhost spool and appears in a separate Machine Spaces surface, not the ordinary agent transcript. The full command is removed from persisted room state after approval/denial.
- The next security boundary is still the scoped filesystem/grant phase. A chosen working directory is not a sandbox and free-form shell approval remains OS-user-wide.

Integrate into existing source boundaries, not a second generic agent executor. Reuse architectural concepts, not World Book's unauthenticated or differently scoped APIs.

## Terminal targets and modes

Class: terminal-origin. Capability type: cmd, powershell, pwsh, wsl, or supervised-server; stable terminalId separate from process PID and display label. Session capabilities advertise discover/read-only, spawn-managed, stdin, stdout, interrupt, and trusted-attach individually. Base mode presents one explicit target and one request/output stream. Dex rooms attach terminals as *resources*, not participants; agents stay in their existing room, can create/rename/archive spaces and attach permitted terminals. A terminal may join multiple spaces only under explicit audited scope rules; never interleave independent commands into one shell without serialized ownership or independent managed sessions.

Managed terminal sessions come first, launched under the user's chosen Windows/WSL identity with an authenticated localhost broker and bounded per-session resources. Existing open windows are discovery-only until a specific verified adapter can attach; generic Windows Console/Windows Terminal cannot be promised universal read/write attachment. Never seize an unrelated terminal by title, PID alone, or port alone.

Request contract examples (names provisional): machine.targets; machine.space.create/attach; machine.path.request; machine.poll.vote; machine.files.list/stat/read/count-lines/search; machine.files.prepare-edit/apply-edit/rename/delete; machine.terminal.exec/status/interrupt; machine.output.page; machine.server.detach/stop; machine.audit.read. Responses identify requestId, roomId, spaceId, terminalId, agentId, triggering Dex messageId, permissionGrantId, execution status and outputId. Keep terminal operation receipts separate from ordinary agent final-response receipts.

## Authorization: human-owned capabilities + agent advisory consensus

Every new physical location must be canonicalized and approved by the HUMAN locally: Allow for one exact operation (nonpersistent), Allow persistently for an exact path/root and capability set (revocable), or Deny (never auto-save a denial as a blanket permission). Grant is bound to local device, authenticated room, allowed agents, canonical root, filesystem identity, allowed operations, duration and an audit version. Folder access does NOT imply arbitrary shell privileges; a shell can escape an approved cwd. List/read/count-lines may be low risk within a granted root; write/rename/delete and free-form shell/interactive stdin require separate explicit capabilities and destructive-action confirmation. Never create a wildcard filesystem grant from a majority vote.

Agent poll is a second-layer room policy, not a replacement for owner approval. Within existing owner-approved capabilities, eligible agents may cast Allow once / Propose persistent scope / Deny with short reasons, and vote yes/no on the chosen action. Persistent scope enlargement ALWAYS returns to the owner for approval. Majority means > half of verified eligible agents, counted once per immutable memberId, with a fixed deadline; a sole active agent may self-vote for preapproved nondestructive work only. Ambiguity, no quorum, timeout or contested high-risk mutation fails closed. Quota-constrained/offline members may be omitted only on fresh, attributable liveness evidence with bounded expiry. Agent-created status toggles are advisory; no agent may falsely exclude another agent to manufacture quorum. User may override participant status and revoke authorization. Avoid repeated nudges/ack loops and preserve an audited digest of poll eligibility/results.

## Filesystem boundary

Never resolve access by string-prefix tests. Resolve canonical paths beneath approved roots for Windows drive, UNC, reparse/junction and symlink cases, and distinguish WSL/Linux roots from Win32 mapped paths. Recheck immediately before OPEN and before atomic rename/write, using handle-based confinement when available. Detect path traversal, aliasing, symlink swaps, unexpected mount changes, excessively large files, invalid encoding, binary content, unsupported metadata and path races; fail closed. Secret/credential paths, SSH keys and arbitrary sensitive files remain denied by default until specifically granted. Private machine paths and outputs must not be passed to a remote model or tab without the user-authorized audience/scope.

Display tree entries with filename, type, bytes, mtime, readable/editable flags, line count when cheap, and file identity/version token. Lazy-load tree branches; paginate directory listings; avoid traversing massive trees by default. Reads: bounded byte/line ranges and optional search with exact source IDs. Edits: preview diff, expected content hash/mtime, atomic temporary file + backup, verify-after-write and conflict detection. No uncontrolled overwrites, recursive deletes, or silent execution of retrieved source.

## Execution and output

Prefer structured, argument-array, shell:false native operations for deterministic list/tree/read/stat/line-count when possible. Arbitrary CMD/PowerShell/WSL scripts require a distinct user-signed execute capability; cwd authorization alone is not a sandbox. If strict containment is promised, use a real OS-level restricted process/identity; otherwise label command execution as OS-user-wide and demand matching approval. Require time, CPU/memory, process-child and output limits; store stdout/stderr separately with exit/signal/cancel reason. Side effects are not retried after unknown execution outcome.

A Dex agent sends one typed command. The ordinary agent transcript gets ONE lightweight reference stub (request ID, resource, status), not bulk output or every progress chunk. A Machine Space stores immutable origin-linked request/result pairs with a visual connector and textual provenance; multiple agents and terminals can filter by initiator/target. Each output box has capped height and internal scroll, preview plus stable paginated outputId/cursor/range recall. Store bounded, retention-controlled full output in an audited localhost spool, not giant chat messages. Long-lived server terminal sessions get a separate Live Servers lane with health, listener identity, rolling logs and an explicit attributable stop (never kill by port alone).

## Interrupted prompt-send recovery update — pending local qualification

The existing exact-once dispatch/recovery boundary is retained. A ChatGPT \`PROMPT_SEND_FAILED\` **does not prove** that the provider failed to receive the message. Since the server has already durably claimed the original dispatch, never automatically re-submit the original prompt after that error. No blanket provider-tab reload, PID fallback, or new agent turn is justified by the error alone.

The current feature-branch implementation (commits following tested baseline \`17ee9b42\`) adds bounded ChatGPT delivery-watchdog evidence: exact request ID, \`blocked\` versus \`uncertain\` phase, and whether the bridge attempted a submission gesture. This is *diagnostic* only, not an authority to retry; a human or another window may still have sent the prompt. The original request stays in capture-only recovery and retains its remaining turn budget in the durable recovery journal. Room status exposes held turns and classification separately from the live relay's zero active turns.

After 45 seconds without resolution, record exactly one \`PROMPT_SEND_RECOVERY_ATTENTION\` incident for the request and surface an exact-tab inspection hint in the Dex UI. Do not keep pinging Eve, Astro, or other room participants. The recovery watchdog operates on its own bounded schedule, never consumes an agent relay turn, and is not a substitute for the existing 11-minute recovery deadline and two-minute passive archive grace. Uncertain original requests maintain the late-final watch and do not replay on timeout.

The native Antigravity capture-layer parser also recognizes a Windows-console-wrapped exact \`RETURN\` preceded *on the same line* by canonical \`BUDGET\` or \`CONTEXT\` controls. It still requires the active exact turn ID, a standalone trailing control block, no open code fence or blockquote, and only canonical trailing controls after the joined marker. This specifically addresses terminal captures where a \`BUDGET:+4\` and \`RETURN\` share a visually wrapped line; ordinary web-origin parsing remains unchanged.

### Safe recovery of a currently interrupted live room

1. Inspect the exact room status from its authorized participant using \`node scripts/dexctl.js status --agy-pid <CURRENT_AGY_PID> --room <ROOM_ID>\` or the Dex status control. Then a separately authorized new \`send\` or \`continue_relay\` creates a *fresh* operation.
5. A fresh independent request can be admitted to the existing room's durable FIFO before recovery ends, but **queued is not delivered**. Do not repeatedly enqueue the same handoff or interpret an old completion as proof that the new recipient got its message.

## Post-disconnection exact tool-result lookup (feature branch, not deployed)

A captured Astro `[[DEX:CMD ...]]` can now persist a transport-owned `[DEX TOOL RESULT]` even if its native notification is unavailable or its terminal disconnects. The same read-only lookup also shows metadata for an authenticated direct `dexctl send`; it never re-executes the original command or creates a new relay.

From `tools/Nexus-Browser`, with the **currently authorized** Antigravity PID and exact room/request IDs:

```powershell
node scripts/dexctl.js tool-result-status --agy-pid <CURRENT_AGY_PID> --room <ROOM_ID> --request-id <CONTROL_ID>
node scripts/dexctl.js tool-result-status --agy-pid <CURRENT_AGY_PID> --room <ROOM_ID> --request-id <CONTROL_ID> --read-result
```

The default lookup reveals only the requesting member's bounded transport states. `--read-result` requires an exact control ID and returns that member's original formatted `[DEX TOOL RESULT]` when there is a captured-command receipt. A direct CLI `send` is instead reported from its original durable FIFO receipt; there may be no captured-command text to retrieve. Another bound member, even in the same room, cannot read the result. Duplicate local target ownership or duplicate stored receipt IDs fails closed.

For scripts use `--json`; ordinary CLI outputs remain JSON by default. To print the shared human-readable formatter for a **new** command, use `--tool-result`. If a network disconnect occurs after a mutating command, `dexctl` returns `DEX_CONTROL_OUTCOME_UNKNOWN` and the *original* `dexRequestId`; it does not automatically retry the mutation. Inspect that same ID with `tool-result-status` instead of issuing a new send. Read-only queries alone may retry with their identical request ID.

This is a **retrieval fallback**, not the requested automatic native delivery. The native one-shot notifier remains staged and unwired until Astro qualifies Windows lock-owner/process-epoch attestation, the private owner-enrollment ACL, exclusive dispatch lease, idle-console safety and exact-session native ACK.
